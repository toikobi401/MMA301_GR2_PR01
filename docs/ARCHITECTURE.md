# Architecture

## Why this shape

Two people work in parallel without blocking each other. One owns the server,
the other owns the clients. The contract between them is `packages/shared`:
when it changes, both sides fail to compile rather than failing at runtime in
front of the examiner.

## The contract rule

Every endpoint returns the same envelope:

```ts
{ ok: true,  data: T }
{ ok: false, error: { code, message, details? } }
```

The client switches on `error.code`, never on `error.message`. Message text is
for humans and can change freely; codes are API surface and cannot.

Codes live in `packages/shared/src/api.ts`. Adding an endpoint means adding its
schemas there first, then implementing the route.

## Request lifecycle

```
Client
  └─ ApiClient.get('/api/v1/thing')          packages/shared/src/http.ts
       │  attaches Authorization header
       ▼
Fastify
  ├─ helmet, cors, rate-limit                apps/server/src/app.ts
  ├─ requireAuth                             apps/server/src/plugins/auth.ts
  ├─ route handler → Zod parse → SQL         apps/server/src/routes/
  └─ error handler → envelope                apps/server/src/plugins/error-handler.ts
```

Any thrown `AppError` becomes a typed failure envelope. Anything else is logged
in full and reported as a generic 500, so internal details never reach clients
in production.

## Authentication

Short-lived access token, long-lived refresh token.

- Access token: JWT, 15 minutes, sent as `Authorization: Bearer <token>`.
- Refresh token: 30 days, stored in `expo-secure-store` on mobile.
- `ApiClient` retries once after a 401, calling `onUnauthorized` to refresh.
- Refresh tokens are revocable through Redis, so logout is immediate.

Passwords are hashed with Argon2id. Never store or log a plaintext password.

## Data access

`postgres` uses tagged templates:

```ts
const rows = await sql`select * from users where email = ${email}`;
```

Values are parameterised automatically. Building SQL by string concatenation is
the one thing that will get the project marked down on security, so do not do
it.

## Why the API is not on Vercel

Vercel runs serverless functions with an execution time limit, no persistent
disk, and no long-lived connections. Both candidate topics need the opposite:
either FFmpeg transcoding sessions that run for minutes, or WebSocket
connections that stay open for an entire game. The API therefore runs as a
container. Vercel hosts the web surface only.

## Adding a feature

1. Define request and response schemas in `packages/shared/src/`.
2. Add the route under `apps/server/src/routes/`, register it in `app.ts`.
3. Call it from the client through `api.get` / `api.post`.
4. Run `npm run typecheck` before pushing.

## Design tokens

`packages/design-tokens` is the only place colours, spacing, radii, and type
scales are defined. React Native reads them through `useTheme()`. The web reads
CSS variables generated by `npm run tokens`.

This is also the Figma bridge: token names here mirror Figma Variable names, so
a design change becomes a value change in one file rather than a hunt through
components.
